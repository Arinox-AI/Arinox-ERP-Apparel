## How to resume (the environment is fragile)

The Codespace has restarted several times; **after any restart**:
1. `docker start apparel-mariadb apparel-redis` (wait about 10 s).
2. The session scratch folder is wiped on a restart. Create it again (`mkdir -p <your scratch path>`) before redirecting any log into it, or the command fails silently and, for example, the test server never starts.
3. Start the hosted-like test site's server: `cd /workspaces/frappe-bench && nohup bench --site hosted.localhost serve --port 8001 > <log> 2>&1 &`, then wait about 40 s for `curl http://hosted.localhost:8001/api/method/ping` to return 200.
4. The API key is in `~/.arinox_hosted_token` (outside the repo). If it is lost, make a new one for Administrator with `frappe.core.doctype.user.user.generate_keys`.
5. If a command says *Too many queued background jobs (600)*, run `bench worker --burst` once (`hosted_tests.sh` already does).
6. Helpers in `arinox-apparel/`: `hosted_sync.sh [groups]` (export from dev, load onto the test site), `hosted_tests.sh [group]`, `hosted_exec.sh file.py`. `hosted_ingest.sh` is held back.
7. **A backgrounded command that starts a subshell (`( ... ) &`) reports "completed" immediately**; use the tool's own background option or watch for a finish marker in the log.

## Gotchas learned (also in the guide)

Server Script sandbox: no classes or imports; module-level helpers cannot see each other (put everything in one function); no `a, b = pair`; no `str.format`, `strftime`, `has_permission`, `get_roles`, `random`; the Administrator holds every role but has no `Has Role` rows. Document-event scripts cannot be called by tests via `bench execute` on an app that is not installed (use the console). A failed submit leaves the in-memory document stale: reload before retrying. ERPNext guards sit in front of ours (fiscal year, over-delivery allowance, currency accounts, warehouse); raise them in test fixtures.
